# Pi Bot 虚拟手机（可选附加能力）

在 Bot 内查看一台已授权电脑上的 Android 手机，需要时手动接管。
不启用此能力不影响文字聊天、资料库或管理端的语音模型配置。

> 当前是受限的单机验证集成，不是通用云手机平台：Linux 执行节点、指定的一台 Android 设备、竖屏 720×1280。不会自动创建实例、登录账号或接入任意 ADB 设备。独立源码仓库：[pi-bot-virtual-phone](https://github.com/TYzzt/pi-bot-virtual-phone)；尚未发布 npm 包。

## 给使用者

1. 打开 Bot 对话，点右上角「更多选项」→「虚拟手机」，与「资料库」「编辑 Bot」同级。设置中的已有入口仍保留。
2. 首次使用选择已经授权给当前账号的执行电脑。页面会展示连接状态并自动刷新预览。
3. 默认只读，点击画面不会操作手机，也不占用人工控制锁。预览失败时使用「重新读取预览」，不要为了修复预览去点接管。
4. 点「接管手机」，阅读说明并确认后才能点击、滑动、使用导航键或输入。
5. 点「结束接管」恢复只读。返回上一页或应用进入后台也会释放；断网时节点超时兜底。

接管期间，Pi Bot 执行器暂停相应命令能力。接管最长 10 分钟；连续 45 秒未成功读取画面或输入自动释放。成功读取画面会续接空闲期限，故此处不是“没有触摸 45 秒必定释放”。失败请求不会续活。

直接输入仅支持最多 1000 个可打印 ASCII 字符，中文使用虚拟手机内的软键盘。输入框遮罩并不代表可安全分享凭据，请勿在聊天或本面板发送密码、验证码。

当前每台电脑只使用节点显式启用的一台手机。Android 和桌面按服务器、账号、Bot 在本机保存选择，不上传、不跨设备同步。旧版无法确认服务器归属的关联不自动迁移；首次需重新选择。失效/撤销绑定不会静默切到另一台电脑，无绑定时也不自动选择唯一电脑；只有有效的 Bot 执行电脑绑定或用户明确选择才能确定目标。

## 架构与边界

```text
Android / 桌面客户端
    → 已认证的 Pi Bot API（核对设备归属、撤销状态）
    → 该账号已授权的执行节点（现有 Hub RPC）
    → PhoneController（白名单、队列、互斥、超时）
    → 本机独立 ADB → 已配置的 Android 设备
```

不要公开 ADB，不需要把 ADB 或截图代理暴露到公网，也不以 Tailscale 为前提。节点通过已有认证连接与服务端通信。

源码入口：

- Android 导航：`android/app/src/main/java/dev/pibot/android/ui/TimelineScreen.kt`
- 面板与生命周期：同目录 `PhoneControlScreen.kt`
- 用户提示：同目录 `PhonePresentation.kt`
- API 归属校验与白名单：`server/src/phone-routes.ts`
- 独立控制组件与锁：`extras/virtual-phone/src/index.ts`（[独立包说明](../extras/virtual-phone/README.md)）
- 执行节点兼容入口：`desktop/packages/service/src/phone.ts`
- 执行器联动：`desktop/packages/service/src/application.ts`

RPC 仅有 `phone.status`、`phone.preview`、`phone.acquire`、`phone.frame`、`phone.input`、`phone.release`。`preview` 无会话且不续租；`frame/input/release` 需要有效人工会话。它不是任意地址转发或通用 shell 接口。

## 管理员部署与配置

### 前置条件

- API、执行节点和客户端都包含相匹配的手机协议，尤其是 `phone.preview`。
- Linux 执行电脑已有正常运行的 Pi Bot、Android SDK ADB、FFmpeg 和 `/usr/bin/flock`。
- 自行安装并启动合法取得的 Android 镜像；Google Play / Google 服务的条款与授权不随本项目开源。
- 管理员必须显式配置 `serial` 和 `adbPort`，无默认值；ADB 固定连接本机 `127.0.0.1`，不扫描、不回退。屏幕仍限制 720×1280 竖屏。内部 `google-play-validation` 仅是兼容客户端的单手机逻辑槽位，不代表已核验 Android 版本或设备身份。不要拿旧 Redroid 链路代替。

### 节点配置

配置文件为执行节点自身数据目录下的 `phone.json`，不是 Bot 的资料库。数据目录由该版本的节点运行方式决定，请核对 `desktop/packages/service/src/paths.ts` 及实际启动环境，勿移动节点身份或凭据文件。

示例（**路径均为占位，必须替换为本机真实绝对路径**）：

```json
{
  "enabled": true,
  "adbPath": "/absolute/path/to/android-sdk/platform-tools/adb",
  "lockPath": "/absolute/path/to/private-runtime/phone.lock",
  "serial": "your-device-serial",
  "adbPort": 5038,
  "ffmpegPath": "/absolute/path/to/ffmpeg"
}
```

示例中的 `5038` 只是示例端口，必须替换为节点实际配置；不要把本机验证值当通用默认。

文件必须属于运行节点的用户，权限为 `0600`，不能是符号链接。锁文件目录使用该用户可写的私有目录；若有其他桥接或受控 ADB 工具，必须共用同一个锁。不要复制生产认证材料到配置示例。

按项目正常构建流程构建节点。首次配置或升级需管理员在合适窗口更新目标节点，保留原身份、认证材料和手机数据；不要为此重启整个 Server 或数据库。本文不自动执行任何安装或重启。

### 验收

1. 手机状态正常，电脑属于当前账号且未撤销。
2. 未接管时 `preview` 返回可解码 JPEG，720×1280，预览前后不占控制锁。
3. 未确认接管时不发送 `acquire/input`；明确确认后取得互斥锁。
4. 主动结束、离开页面、进入后台及节点超时均能释放，失败请求不续活。
5. 非所属账号、撤销设备、失效会话、非法坐标和非白名单事件必须拒绝。
6. 会话绑定配置快照，变更端口/设备/锁路径或删除配置后旧会话不得继续输入；重新核验目标后再接管。
7. 操作代理和运维工具必须读取同一份有效配置，显式传入 host、端口和 serial，再只读核验指纹/AVD 名称。组件不保存设备指纹，外部复用同 serial 不在其身份校验能力内。

自动化单测不能替代安卓真机上的小屏、大字体、网络断开和触摸坐标验收。

## 安全与隐私

- 手机画面和输入通过已有认证连接传输，不作为聊天消息保存；API 设置 `no-store`。不要自行增加记录截图、输入正文或令牌的访问日志。
- 授权互斥仅约束合作的 Pi Bot 执行器及共用锁的工具，**无法阻止外部直接运行原始 ADB**。宿主机访问权限仍由管理员控制。
- 本组件不保存手机账号，也不自动输入密码或验证码。
- 独立开源只包含必要源码、示例和测试。不能带入 `.env`、节点凭据、模拟器磁盘、ADB 密钥、数据库、日志、真实截图或账号数据。
- 开源发布前应单独审查许可证与第三方依赖；Pi Bot 源码使用其仓库许可证，不代表 vphone 所有历史内容或 Android 镜像已经获得相同授权。

## 语音模型不受影响

虚拟手机与语音通话是两项独立能力。本轮手机界面改造不修改服务端或管理端语音模型选择、不覆盖管理员配置、不把通话模型写死为单个名称，也不改变 Bot 的文字模型。具体支持的语音供应商、模型与音色请以正在使用的版本及管理端实际配置为准，不能用模型名配置成功或 WebSocket 建连代替真实音频验收。

## 排障

| 表现 | 建议 |
| --- | --- |
| 预览提示“人工控制会话已失效” | 核对节点是否支持 `phone.preview`。通常是新 API 与旧节点协议不匹配；不用先接管，也不必先重装 APK。 |
| 电脑离线 | 检查该执行节点是否启动、登录并保持认证连接。API 健康不等于节点在线。 |
| 手机未就绪 | 检查 `phone.json` 的归属/0600权限/绝对路径，再用本机 ADB 5038 检查指定设备；别误查默认 5037 的旧设备。 |
| 画面读取超时 | 检查网络、ADB 截图、FFmpeg 转换和节点负载；一次次盲目接管不会修复截图。 |
| 截图尺寸不支持 | 当前仅支持 720×1280 竖屏。由管理员确认镜像显示配置，勿擅自清除数据。 |
| 手机被占用 | 预览可继续尝试；等对方释放锁，勿强行绕过互斥。 |
| 输入未送达 | 核对有效接管会话和网络；系统不自动重发，避免重复点击或重复提交。 |
| 只有原 vphone 网页正常 | 原网页可能连接的是另一台设备，不代表 Pi Bot 的认证 API→节点→指定设备链路正常。 |

报障请提供时间、页面提示和应用版本，不提供账号密码、验证码、密钥或带隐私内容的截图。

## 开发与测试

```sh
# 已按 android/README.md 配好本机 SDK、Java 和依赖
cd android
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

发布 APK、安装到用户手机、生产部署、重启服务与公开发布附加组件均是独立操作，不由上述测试步骤自动执行。
