# 已保存授权

桌面端（Windows、Linux、macOS）和 Android 的路径访问请求提供「拒绝 / 仅本次允许 / 一直允许」。界面显示服务器生成的权限范围；点击「一直允许」会再次确认该范围。设置页的「已保存授权」可查看、刷新、撤销规则，并查看最近 100 条授权及使用日志。

默认保存范围为 **当前账号 + 实际执行电脑或云端环境 + 读取 + 指定文件或目录**。目录包含子路径，单个文件不包含同名前缀或其他文件。读取覆盖列目录、读取及搜索文件，不包含写入、删除、命令工作目录或任意命令执行。写入、命令和旧版未声明操作类型的宽泛请求仍需逐次确认，「一直允许」不可用。

## 执行链路

- 新执行端的 `request_outside_access` 声明 `access: read | write | execute`（默认 read），在本机解析真实路径，拒绝整个磁盘、整个主目录和不存在的读取资源，并提供文件/目录类型。服务端从真实运行绑定生成执行目标，不采用客户端指定的电脑 ID。
- `POST /approvals/:id` 接受 `approve`、`reject` 和 `approve_always`。审批必须属于当前账号、未过期、尚未决策且任务仍有效。持久规则和 grant 日志与审批决策在同一数据库事务中提交。
- 规则由 `0020-saved-authorizations` 迁移创建。授权保存于服务端，重启客户端或服务端后仍有效。同一活动范围去重；撤销保留历史，重新授权创建新记录。
- 本机路径工具解析真实路径后，通过绑定用户、Bot、执行电脑和运行的短期令牌调用内部 `POST /agent/authorizations/check`。服务端按账号、电脑、读取操作和规范资源边界匹配并写入 use 日志。本机不把持久授权缓存成任务级宽泛目录权限。
- 云端操作由 API 根据实际环境和操作类型匹配规则，再将匹配的资源交给 guest 校验；读取规则不会传给写入、命令或浏览器操作。guest 不对授权根目录再次跟随替换后的符号链接。
- 路径使用平台对应的分隔符，拒绝相邻目录前缀、越界 `..`、根目录、Windows UNC 和备用数据流。本机及 guest 继续校验符号链接解析后的路径。执行端发送规范路径，服务端保留路径组件大小写，避免扩大到 Windows 中显式区分大小写的目录。
- 读取、撤销和日志接口均校验账号所有权：`GET /authorizations`、`DELETE /authorizations/:id`、`GET /authorizations/logs`。撤销在事务提交后影响后续权限检查，已经开始的操作可能完成。服务器或网络验证失败时不会自动放行。旧服务端缺少规则接口时回退到显式单次审批。

单次授权限当前任务和对应操作类型，兼容旧版已有单次审批。「一直允许」仅建立文件工具的读取权限，不改变现有命令工具、操作系统账号或远程环境的隔离能力。

## 验证

`server/tests/authorizations.test.ts` 使用真实 PostgreSQL 和 API 验证保存、后续任务复用、签名桌面调用、跨用户/电脑隔离、越界、写入/命令隔离、撤销、审批失效和审计日志。`desktop/tests/library.test.ts` 验证真实文件工具、符号链接和运行中撤销。`desktop/tests/client-settings.test.ts` 通过真实界面桥接验证范围确认、决策失败后的重试，以及设置页撤销反馈。

上线需要同时部署服务端迁移和新版执行端。旧版未提供明确操作及资源类型时不允许创建持久规则；客户端会展示原因。
