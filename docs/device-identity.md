# 设备身份与执行设备决策策略

> 实现见 PR #68，问题来源 issue #62，原始 spec 为 issue #67。本文是长期设计参照，修改设备相关代码时应先对照本文。

## 1. 背景

- **重装后设备分裂**：桌面端重装系统或丢失私钥后，以公钥作为唯一身份，会被当成新设备注册，同一台电脑在账号下出现多条记录，账本与历史随之割裂。
- **AI 无法判断在哪台机器执行**：消息没有来源设备信息，AI 不知道"当前这台"指哪台；也没有"哪台机器做过什么"的经验，只能猜。

核心原则：**来源（消息从哪发）与执行目标（任务在哪跑）严格分离**；手机是云端入口，不是执行设备。

## 2. 策略

### 2.1 设备身份（首要）

- 桌面端注册时附带版本化 SHA-256 硬件指纹（macOS 硬件 UUID；Linux、Windows 使用等价硬件标识）。不传输原始硬件序列，不写入公开日志。采集失败时退回原公钥注册，不伪造稳定性。
- 匹配顺序：同账号未吊销设备的公钥 → 同账号内硬件指纹**唯一命中**。唯一命中时**自动归并，无需用户确认**：沿用原 device_id、替换新公钥、记录密钥轮换事件，并提示"已识别为 X（重装后重新绑定）"。0 条或多条命中则新建设备。
- 轮换后旧凭据、旧长连接立即失效，不能继续冒充该设备。
- 安全边界：指纹只做同账号内辅助身份恢复，**不是认证凭据**，仍需已登录账号授权注册；不跨账号合并、不复活已吊销设备、不按同名或平台自动合并。
- 迁移与限制：
  - **老设备需先升级桌面端**，用原密钥注册一次以补上指纹。
  - **丢失密钥且从未留过指纹的设备，原 device_id 无法找回。**
  - 硬件更换或克隆无法保证自动恢复；Linux machine-id 回退不保证重装后稳定。

### 2.2 消息来源设备

- 每条用户消息记录来源（桌面设备 id 与可读名称 / 手机云端入口 / web），并注入 AI 上下文。
- 同一对话中不同端发消息，来源互不覆盖；历史无来源的消息标为"未知"。
- 手机统一视为云端入口，"当前设备"不指代任何历史关联电脑；来源设备 id 需校验属于当前账号。

### 2.3 端能力记忆

- 按智能体记账的**经验账本**，不是实时监测：记录哪台设备（真实 device_id）执行过什么、具备哪些能力（shell / browser / 文件）、已核实的文件路径、最后核实时间与证据来源。
- 任务收尾自动更新；不扫描磁盘、不定时探测，不因工具存在就视为已授权，不把不同机器的同名路径当作同一资源。
- 相悖条目不盲目覆盖：保留来源，由 AI 分析判断并核查后更新。
- 手机仅是云端入口，不占设备条目。记忆不扩大权限，也不承诺历史文件仍然存在。

### 2.4 执行设备决策链

优先级从高到低：

1. 用户本轮明确指定
2. 端能力记忆唯一命中
3. 纯文字 / 搜索 / 联网类任务，默认 cloud
4. 仍不确定（多台可能、资源来源冲突）则**询问用户**，不猜

规则：

- 选定后用一句话说明选了哪台及原因，用户可一句话覆盖。
- 选中的设备离线时**立即提醒不可用**，并给出由用户选择的替代方案；**不排队、不自动换机**。任务开始后保持执行节点，避免重放未知外部操作。
- 例外：用户明确配置的周期目标保留独立等待策略，可等待其固定设备，与交互任务无关。

## 3. 范围与边界

- 涉及：桌面端、服务端、智能体运行时（提示词 / 决策逻辑 / 记忆）。
- iOS 端不涉及设备身份（按云端入口处理）；Android 仅设备列表展示层，协议保持兼容。
- 服务端迁移 0030、0031 增加指纹 / 密钥代数、来源与端经验字段。
